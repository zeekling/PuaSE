核心能力

🔍

隐含需求解析

5 步法：捕获显式需求 → 推导隐含需求 → 识别约束 → 拆解任务 → 确定优先级

📊

代码库成熟度评估

快速判断项目处于初期/成长/成熟阶段，自动适配策略

🏗️

先架构后代码

不读通架构不写代码，不画清依赖不修改。架构分析作为所有决策的上下文基础

🔄

专家委派体系

18 位专家 Agent 覆盖架构、开发、DBA、安全、审查、巡检全链条

🧊

上下文隔离原则

所有专家任务在独立子 Agent 会话中执行，主上下文仅保留编排决策所需最小信息，避免专家工作日志污染编排层

🎯

技能编排优化

将执行类 Skill（如 brainstorming/TDD/调试）翻译为委派策略交给对应 Agent，自身不执行技能中的"你来做"指令

📋

KPI 验收卡

没有 KPI 卡的交付叫自嗨。编译/测试验证 + code-reviewer 审查 + quality-inspector 巡检 + security-expert 审计 + 影响面确认，五者缺一不可

⚡

异常处理 · 压力升级

指数退避重试、Agent 熔断降级、L0-L4 压力升级、关键路径保护

快速上手

PuaSE — 终端
$ @PuaSE 帮我分析项目架构
→ 启动 architect 子 Agent（独立上下文）...
├─ 目录结构 · 模块依赖 · 数据流
├─ C4 模型 · ADR · 风险评估
└─ 子 Agent 返回结果摘要 ✅
$ @PuaSE 开发一个新的 Java 功能
→ 子 Agent 1: architect 架构设计
→ 子 Agent 2: java-developer 编码实现
→ 三家并行验收（各自独立上下文）:
├─ security-expert 审计 ✅
├─ code-reviewer 审查 ✅
└─ quality-inspector 巡检 ✅
$ @PuaSE 审计代码安全
→ 委派 security-expert 子 Agent...
