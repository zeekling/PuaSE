## 为什么这些改动重要

### 1. 更低的上手门槛

很多用户"一试就放弃"只是因为第一步踩坑：符号链接配错、子 Agent 没注册上、`opencode.json` 写错被静默忽略。

**v0.2.4 做了三件事解决这个问题：**

- 把前置条件写死在文档里：你至少需要 OpenCode + Node.js ≥ 18，而不是“装了再看”。
- 把安装后的验证写死：重启 OpenCode → 确认默认 Agent 是 PuaSE → 跑一条测试指令。跑不通？看哪里出问题，马上定位。
- 放弃"脚本一键安装"的广告式写法，统一用 `npm install @zeekling/puse`，步骤最简。

### 2. 本地调试不再靠猜

`npm pack` 生成本地 tarball 后，你可以用 `npm install ./zeekling-puse-x.x.x.tgz` 在本地先装好再发。官网快速开始把这条路径写清楚了，方便你在 npm publish 之前先做集成测试。

### 3. 文档成为"变更的同步镜像"

每次 PuaSE.md 修改，对应的 README 和官网页面都必须同步更新。v0.2.4 的这次改动是一次对这条规则的再次实践：官网的"快速开始"已经与最新安装方式完全对齐。

## 适合谁用

- **已经用 OpenCode，但觉得 AI 的产出质量不稳定**  
  PuaSE 的 KPI 门禁、HARD-GATE、委派链和复盘机制把"完成了"变成"完成了，附证据"。

- **团队协作写代码，担心 AI 跳过审查或绕过程序**  
  你的架构图、风险列表、安全报告、KPI 卡不是推荐步骤，是硬性输出物。AI 门外偷懒？门禁先挡住了。

- **想自己控制成本，不同 Agent 用不同模型**  
  `config_template.json` 按 Agent 级别配模型，便宜的 Agent 用轻量模型，关键决策 Agent 用强模型。官微成本优化。

## 开始使用

```bash
# 1. 安装
npm install @zeekling/puse

# 2. 在 opencode.json 中启用
# { "plugins": ["@zeekling/puse"] }

# 3. 重启 OpenCode，确认 Agent 为 PuaSE

# 4. 一条命令验证
@PuaSE 帮我分析项目架构
```

> 本地调试：`npm pack` → `npm install ./zeekling-puse-1.0.0.tgz`，一切就绪再 `npm publish`。
