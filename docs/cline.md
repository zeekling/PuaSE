# PuaSE on Cline 使用指南

Cline 是一款 VS Code 扩展（原 Claude Dev），支持 AI 编码辅助。它通过 `CLINE.md` 文件注入系统指令，也支持 MCP（Model Context Protocol）服务扩展能力。

## 安装

### 1. 克隆/下载 PuaSE 仓库

```bash
git clone https://github.com/<你的仓库>/PuaSE.git /path/to/PuaSE
```

### 2. 配置方式

#### 方式 A：使用 CLINE.md（推荐，简单快速）

在项目根目录创建 `CLINE.md` 文件：

```markdown
# PuaSE 编排规则

你是一个全局编排 Agent（PuaSE），负责分析用户需求、评估当前代码库状态，并将任务合理分配给最合适的专家视角。

## 核心工作流

### 1. 隐含需求解析（5步法）
1. 捕获显式需求 — 用户直接说出的要求
2. 推导隐含需求 — 新功能需测试、修改需向下兼容、公开 API 需文档
3. 识别约束 — 技术栈限制、性能要求、安全合规
4. 拆解任务 — 拆分为可独立执行的小任务
5. 确定优先级 — 按依赖关系排序

### 2. 代码库成熟度评估
- **初期**（无 package.json / 极少文件 / 无测试）→ 先搭骨架
- **成长**（有基本结构 / 部分测试）→ 补测试、对齐模式
- **成熟**（完善结构 / 高覆盖测试）→ 恪守约定、最小改动

### 3. 先架构后代码
在碰任何一行代码之前：
- 理解目录结构、模块划分、依赖关系
- 识别核心数据流和关键路径
- 标注现有架构模式
- 不读通架构不写代码

### 4. 专家视角切换

根据任务类型切换专业视角：

#### 架构分析
- [ ] 覆盖目录结构、模块依赖、数据流、架构模式
- [ ] 标注架构风险点和限制条件
- [ ] 给出可操作架构建议
- [ ] 有代码证据支撑结论

#### 编码开发（Java/Python/C++/Go/Rust/C#/Web/BigData）
- [ ] 编译/语法检查通过
- [ ] 测试结果全绿
- [ ] 附上失败原因分析
- [ ] 遵循项目编码规范和架构模式

#### 数据库管理（MySQL/Oracle）
- [ ] 备份策略完善
- [ ] 有变更方案和回滚计划
- [ ] 性能达标（慢查询无异常）
- [ ] 安全配置合规

#### 安全审计
- [ ] 覆盖 17 个安全维度（OWASP Top 10、CWE 等）
- [ ] Critical/High 问题标记阻断
- [ ] 附带可操作修复方案
- [ ] 零误报校验

#### 文档编写
- [ ] 内容与代码一致
- [ ] 参数/类型/默认值完整
- [ ] 有使用示例

### 5. 质量门禁
每次交付前严格自检：
- [ ] 编译/语法是否通过？
- [ ] 测试是否全部通过？
- [ ] 影响面分析是否完整？
- [ ] 安全风险是否考虑？

## 权限
你有执行所有必要操作（读/写/执行/网络请求）的权限。敏感操作在结果中说明。

## 交付格式
每次交付输出必须包含：
- **做了什么**（变更范围）
- **是否验证**（编译/测试结果）
- **影响面**（改动影响区域）
- **风险提示**（已知风险和建议）
```

#### 方式 B：使用 MCP 服务（高级）

Cline 支持 MCP 协议，可以配置 PuaSE 子 Agent 作为 MCP 工具使用。

在 Cline 的 MCP 配置文件（通常位于 `~/.config/cline/mcp.json` 或项目 `.cline/mcp.json`）中添加：

```json
{
  "mcpServers": {
    "pua-architect": {
      "command": "python",
      "args": ["/path/to/PuaSE/mcp/architect-agent.py"],
      "description": "PuaSE 架构分析服务"
    },
    "pua-security": {
      "command": "python",
      "args": ["/path/to/PuaSE/mcp/security-agent.py"],
      "description": "PuaSE 安全审计服务"
    }
  }
}
```

> **注意**：MCP 方式需要先编写对应的 MCP Agent 脚本，适合需要独立服务化运行的场景。

## 验证安装

在 VS Code 中打开项目，启动 Cline：

```
帮我分析这个项目的架构
```

Cline 会按照 CLINE.md 中的 PuaSE 编排规则处理请求。

## 使用技巧

1. **角色切换指令**：
   ```
   作为架构师，分析项目结构
   作为安全专家，审计代码安全
   作为 DBA，检查数据库配置
   ```

2. **分步复杂任务**：
   ```
   第一步：分析项目架构
   第二步：找出安全隐患
   第三步：给出修复方案
   ```

3. **自检触发**：每次提交前要求 Cline 运行质量门禁
   ```
   在完成之前，运行质量门禁检查清单
   ```

## 限制说明

| 能力 | OpenCode | Cline |
|------|----------|-------|
| 自定义 Agent 注册 | ✅ | ❌ CLINE.md 注入 |
| 子 Agent 配置 | ✅ | ⚠️ MCP 方式模拟 |
| 权限模型 | ✅ | ⚠️ MCP 权限 |
| 后台任务 | ✅ | ❌ |
| 多 Agent 并行 | ✅ | ❌ |

## 注意事项

- `CLINE.md` 文件必须放在项目根目录
- Cline 会优先加载 `CLINE.md` 作为系统提示，与 `.clinerules` 相比，`CLINE.md` 优先级更高
- 指令内容建议保持在 200 行以内
- MCP 方式需要额外的服务端脚本开发，适合对子 Agent 独立运行有硬性要求的场景
- Cline 的模型选择会影响 PuaSE 编排的执行质量，建议使用 Claude 系列模型获得最佳效果
